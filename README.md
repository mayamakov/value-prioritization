# Reproducibility package

**LLMs and Physicians Prioritize Preventive-Care Patients by Different Values**

This repository contains the code and data needed to reproduce every analysis,
figure, and table in the manuscript. The pipeline runs end-to-end on a laptop
(CPU only) and regenerates the paper's outputs from the raw ranked patient
pairs.

## Quick start

```bash
# 1. Install dependencies (Python 3.11 or 3.12)
pip install -r requirements.txt

# 2. Reproduce everything
cd code
python run_all.py
```

That single command runs the whole pipeline and writes all figures and tables to
`results/`. On a typical laptop it finishes in a few minutes. Read the
`MANIFEST` printed at the end: every stage should say `PASS`.

To recompute the SHAP attributions from scratch (needs a GPU, a few minutes):

```bash
python run_all.py --with-shap
```

By default the pipeline reuses the **precomputed** SHAP output shipped in
`results/ethical_shap_per_patient.pkl`, so SHAP-based figures reproduce exactly
without a GPU.

## The pipeline, stage by stage

`run_all.py` executes each stage as an isolated subprocess (memory is released
between steps, and a single failure does not abort the run):

| Stage | Script(s) | What it produces |
|-------|-----------|------------------|
| **A** — pair build (CPU) | `rebuild_pair_csvs.py`, `make_topN_frozen.py`, `stage2_top_and_pairs.py` | 300 common pairs; Top-N rankings; per-rater value profiles; agreement matrices |
| **B** — SHAP (GPU, optional) | `stage1_ethical_value_mapping.py`, `raw_shap_clustering_FIXED.py` | per-patient SHAP attributions; raw-SHAP clustering. *Reused from shipped pkl unless `--with-shap`.* |
| **C** — normalize (CPU) | `normalize_tables.py` | z-scores each profile table per axis across the 26 raters |
| **D** — figures (CPU) | `make_figS2.py`, `paper_figures_CORRECTED.py`, `generate_all_figures_FINAL_FIXED.py`, `figR_*.py` | all main + supplementary figures |
| **E** — tables (CPU) | `run_to_run_agreement.py`, `family_distances.py`, `shap_mapping_correlation.py`, `print_all_tables_v10.py` | rollout stability; developer-family distances; raw-vs-mapped correlation; manuscript tables T3-T13 |

## The study in brief

Ten physicians and sixteen LLMs each ranked the same set of preventive-care
patients through pairwise choices. Every rater's choices were reduced to a
common set of **300 patient pairs**, and each recommendation was mapped onto one
of five ethical axes (utility-oriented beneficence, priority-to-need
beneficence, non-maleficence, patient empowerment, resource justice). Two
complementary estimators — a **RankNet** pairwise preference model with **SHAP**
attribution, and a direct **pairwise logistic-regression** decomposition —
recover each rater's operational value signature, which are then compared
between physicians and LLMs and across LLM developer families.

## What is *not* reproduced here (and why)

The **LLM ranking step** — querying the sixteen models to obtain their pairwise
choices — is **not** part of this pipeline. It requires paid API access to each
provider and is inherently non-deterministic. The models' choices are instead
shipped as fixed inputs under `data/physicians_results/`, so every downstream
analysis is fully deterministic and reproducible from those files. Anyone who
wants to regenerate the raw model choices can do so with their own API keys
using `rank_with_llm.py` from the original codebase; the results will vary
slightly run-to-run, which is exactly the run-to-run stability the paper
quantifies.

## Participant privacy

The ten physicians are identified throughout the code, data, and outputs only by
the anonymised labels used in the manuscript — `fm_1`–`fm_5` (family medicine)
and `ph_1`–`ph_5` (public health). No participant name appears anywhere in this
repository, including in the ranked-pair filenames under
`data/physicians_results/` and in every shipped results table.

LLM raters are identified by model name, since they are not human participants.
Three legacy keys are retained for backward compatibility with the saved
artefacts: `doctor8` = GPT-4o-mini, `doctor9` = GPT-5-mini, `doctor10` =
Llama-4 Maverick. The authoritative key-to-label map is
`panel_config.DISPLAY`, and `results/rater_keymap.csv` is regenerated by the
pipeline.

## Reproducibility notes

- **Determinism.** Given the shipped inputs, Stages A, C, D, and E are fully
  deterministic. Re-running `run_all.py` reproduces identical CSVs and figures.
- **Precomputed SHAP.** SHAP attribution (Stage B) is GPU-bound; its output is
  shipped so the default CPU run reproduces every SHAP-based figure exactly. Use
  `--with-shap` to recompute it.
- **Sanity checks.** Several scripts print sanity lines you can check against the
  manuscript (e.g. `raters present=26/26  common pairs=300`, and the Top-50
  physician/LLM means in `make_topN_frozen.py`).
- **Pseudonymisation.** Physicians appear only as `fm_1`-`fm_5` / `ph_1`-`ph_5`
  (displayed FM-1...FM-5, PH-1...PH-5). No personal names appear anywhere.
- **Paths.** `run_all.py` links the data files into the working directory under
  the names the analysis scripts expect, so the original code runs unchanged.


## Prompt templates and model versions

- `code/rank_with_llm.py` — the prompt templates (system prompt and per-pair user
  prompt) sent to the LLMs, plus the provider-agnostic API-call wrappers. Supply
  your own key via the `LLM_API_KEY` environment variable to re-query the models.
- `data/model_versions.csv` — the exact API model string used for each of the 16
  LLM raters (developer and version identifier), matching the manuscript's data
  availability statement.
